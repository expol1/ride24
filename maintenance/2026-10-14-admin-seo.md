## User workflow

Admin → SEO → Refresh locations → choose a destination → Prepare PL and EN (or manually edit/import the JSON format from the supplied preview.html) → review both languages → Save draft → approve → Publish PL and EN.

The module registers current pages as published without changing them. New topics group multiple partner pickup points by country/region/city/airport. Only active partners with active fleet or an enabled API are included. No automatic publication occurs. Plain text is escaped and rendered through a fixed responsive HTML template. Public URLs are immutable after publication. Metadata, reciprocal hreflang links and a language switch are provided.

Revision history allows an older text to be restored as a draft. Google notes can be entered and incorporated into regenerated drafts. Re-publication uses the existing addresses. Publication locks and revision checks prevent stale edits and concurrent double publication.

Both language files and sitemap are committed atomically via the Git Data API. Current page hashes are checked before replacement; changes outside the SEO panel are protected. Main is advanced only without force. An identical successful retry is recovered without another commit. Sitemap processing preserves unrelated entries. Public deployment is checked independently using a per-revision marker before any Google sitemap submission.

## Configuration and limits

Gemini: create a separate Google AI Studio project on Free without billing, paste its API key into admin SEO settings, and explicitly confirm the Free tier. The module uses the documented `gemini-3.8-flash` REST endpoint with JSON output and low thinking. No search grounding, image generation or OpenAI fallback is used. Default maximum: three attempted AI calls/day (UTC), adjustable 1–10. Turn on automatic drafts only after configuring the Free project. The hourly job refreshes topics and generates at most one queued draft per run; it cannot publish. Provider limits may stop a request. The operator must verify the project's billing tier; the API key alone cannot attest that billing is disabled.

Secrets are encrypted in dedicated Vault entries. New SEO tables have RLS enabled, with no anon/authenticated privileges. The Edge endpoint validates the Supabase Auth user and stored profile admin role before accessing credentials. The internal cron path validates its separate Vault secret. Neither credentials nor upstream response bodies are returned to the browser.

OAuth uses an expiring, hashed, one-use state tied to a verified admin, PKCE, and separate SEO refresh tokens. Ads tokens and campaigns are not modified. The callback fails closed if permission/refresh token is missing and leaves previous connections intact.
